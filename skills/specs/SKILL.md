# 仕様（Specs）

このリポジトリの仕様は **ルート直下の `specs/`** に Markdown で格納する。

## 仕様の場所

- **ディレクトリ**: `specs/`（プロジェクトルート）
- **形式**: `.md` ファイル（1機能・1テーマごとに1ファイルを推奨）

## 仕様の確認

1. **一覧**: `specs/` 内の `.md` を列挙し、どの仕様があるか把握する。
2. **読む**: 対象の仕様ファイルを読み、表示条件・対象ファイル・実装詳細を把握する。
3. **実装との整合**: 必要なら「対象ファイル」に記載されたコードや設定を開き、仕様どおりか確認する。
4. **報告**: 確認結果を簡潔にまとめる（問題があれば差分や修正案を提示する）。

## 仕様の更新

1. **対象を特定**: ユーザー指示または Issue から、更新対象の仕様ファイル・セクションを決める。
2. **既存形式に合わせる**: 同じファイル内の見出し・表・コードブロックのスタイルを崩さない。
3. **関連を明示**: Issue 番号・対象ファイル・表示条件など「関連」セクションや表を必要に応じて更新する。
4. **実装詳細**: コード例を更新する場合は、実際の実装（対象ファイル）と一致させる。

## 新規仕様を追加する場合

- `specs/` に新しい `.md` を追加する。
- 次の構成を推奨:
  - タイトル（# 機能名）
  - 関連（Issue リンクなど）
  - 対象ファイル（表）
  - 表示仕様 / 動作仕様（条件・優先順位など）
  - 実装詳細（必要ならコード例）

## 注意

- 仕様は「実装の正」なので、実装を変えたら仕様も合わせて更新する。
- 曖昧な表現は避け、条件・ID・ファイルパスは具体的に書く。
